# 2026년 8월 6일 업데이트 내역

오늘 진행된 주요 버그 수정 및 기능 개선 내역을 정리한 문서입니다.

## 1. 패키지 구매 백엔드 API 연동 (실제 DB 반영)
- **개요:** 기존에 프론트엔드 UI 화면에서만 임시로 가짜 숫자가 올라가던 옥구슬 패키지 구매 기능을 실제 서버 데이터베이스(Supabase)와 연동했습니다.
- **주요 작업 내용:**
  - `apps/user-web/src/app/api/package/purchase/route.ts` API 생성.
  - 사용자가 패키지를 구매하면 서버에서 트랜잭션을 열고, USDT 잔액을 차감한 뒤 옥구슬(JADE) 및 홍바오(URC) 자산을 추가하도록 구현했습니다.
  - 패키지 구매 기록을 `user_game_machines` 테이블과 통합 원장 `ledger_entries`에 영구 기록하도록 추가했습니다.
  - 프론트엔드(`page.tsx`)의 구매 버튼을 해당 API와 연동하여 통신 성공 시에만 실제 잔액을 새로고침하도록 로직을 변경했습니다.

## 2. Vercel 배포 빌드 에러 해결
- **문제 현상:** `page.tsx`에서 패키지 구매 후 최신 잔고를 동기화하기 위해 호출한 `fetchUser()` 함수가 `useEffect` 내부에 지역적으로 선언되어 참조(Reference) 에러가 발생하여 Vercel 서버 빌드가 실패했습니다.
- **해결 방안:** 전역적으로 접근 가능한 `loadBalances(userId)` 함수를 대신 호출하도록 수정하여 타입스크립트 컴파일 에러를 해결하고 성공적으로 서버에 배포했습니다.

## 3. 통합 장부(Ledger) 거래 유형(tx_type) 마이그레이션
- **문제 현상:** 게임 참여 시 DB에 거래 내역을 기록하는 과정에서 `transaction_type`이라는 잘못된 컬럼명을 참조하고, DB에 허용되지 않은 새로운 거래 유형값(`PACKAGE_BUY`, `GAME_WAGER` 등)을 삽입하려다 제약 조건 위반 에러(`check_tx_type`)가 발생했습니다.
- **해결 방안:**
  - `purchase`, `participate` API 라우트 내 쿼리문에서 `transaction_type`을 올바른 `tx_type`으로 일괄 수정했습니다.
  - 데이터베이스의 `check_tx_type` 제약 조건을 해제하고 새로운 거래 유형(`PACKAGE_BUY`, `PACKAGE_BONUS`, `GAME_WAGER`, `GAME_WIN`)을 모두 허용하도록 업데이트하는 마이그레이션 도구(`api/migrate/route.ts`)를 작성 및 실행하여 DB 설정을 완벽히 반영했습니다.

## 4. 다국어 지원: 자동 배팅 및 알림창 번역 누락 수정
- **문제 현상:** 중국어 및 영어 모드를 사용 중임에도 불구하고, 일부 알림창이나 종 모양(🔔) 알림 모달에서 과거에 기록된 한국어 텍스트가 그대로 노출되는 문제가 있었습니다.
- **해결 방안:**
  - `page.tsx` 내부의 자동 배팅 설정, 게임 시작, 에러 팝업(`alert()`) 문구들을 하드코딩된 한국어에서 현재 활성화된 `lang` 상태값에 따라 동적으로 번역되도록 조건문을 추가했습니다.
  - 알림 모달 창 렌더링 로직(`n.title.includes(...)`)을 수정하여, 이전에 한국어로 기록되어 배열에 남아있던 "게임 참여 완료" 등의 과거 기록(Legacy string)까지 현재 언어 모드에 맞춰 즉시 번역되어 표시되도록 렌더링 규칙을 고도화했습니다.
